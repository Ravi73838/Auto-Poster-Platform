# Contract Synchronization Guide

## 1. Overview & Single Source of Truth

The Auto Poster Advertising Platform enforces a **Single Source of Truth** architecture. All shared types, validation schemas, UI design tokens, localization strings, constants, and the unified HTTP API client originate in one place:

```
api/src/contract/
├── api-client/       # Unified HTTP client for web, mobile, and testing
├── constants/        # System enums, roles, statuses, and pricing configuration
├── i18n/             # Translations (en, hi, gu) for auth, campaigns, errors, kyc, etc.
├── money/            # Pure integer paise math, currency formatting, pricing formulas
├── time/             # IST calendar day math and time utilities
├── tokens/           # Semantic design tokens with verified WCAG contrast
├── types/            # DTOs, domain models, and API response structures
└── validation/       # Zod schemas for runtime request/response validation
```

This folder is **pure TypeScript and JSON**. The code is automatically synchronized into:
- `web/src/shared/`
- `mobile/src/shared/`

Developers **never** edit files directly in `web/src/shared/` or `mobile/src/shared/`. All modifications must be made in `api/src/contract/`, followed by running the synchronization script.

---

## 2. Purity Rules & Verification

To ensure universal compatibility across Node.js, modern web browsers, and React Native / Expo Metro runtimes, all files in `api/src/contract/` must satisfy strict purity criteria:

1. **Permitted Dependencies**:
   - Only pure TypeScript, JSON, and `zod` are permitted.
2. **Forbidden Dependencies**:
   - **Node.js Built-ins**: `fs`, `path`, `crypto`, `os`, `child_process`, `process`, `Buffer` (use browser-safe or isomorphic standards).
   - **Server / DB Frameworks**: `@prisma/*`, `express`, `argon2`, `bullmq`, `ioredis`, `helmet`, `cors`.
   - **UI Frameworks**: `react`, `react-dom`, `react-native`, `expo`.
3. **Escapes Out of Contract**:
   - Contract files must not import files outside `api/src/contract/`.

The synchronization script automatically performs static AST and regex scans before writing any file. If an impure import is detected, synchronization halts with an error and descriptive diagnostic message.

---

## 3. How Synchronization Works

The sync process is executed by `api/scripts/sync-shared.ts`:

1. **Purity Scan**: Every file in `api/src/contract/` is verified against the banned import list.
2. **Transformation**:
   - Standardizes line endings to LF (`\n`).
   - Injects a standard autogenerated banner at the top of every file:
     ```typescript
     /**
      * GENERATED FILE - DO NOT EDIT.
      * Source: api/src/contract/...
      * Run 'npm run sync:shared' in api/ to update.
      */
     ```
3. **Target Sync**:
   - Copies transformed files to `web/src/shared/` and `mobile/src/shared/`.
   - Removes any orphaned files in the target directories that no longer exist in the contract.
4. **Manifest Generation**:
   - Generates a `.generated-manifest.json` file in each target folder containing file names, relative paths, and SHA-256 content hashes.

## 4. Commands & Modes

### 4.1 Synchronize Contract
To propagate changes from `api/src/contract/`:
```bash
# From api directory:
cd api
npm run sync:shared

# Or from repository root:
npm run sync
```

### 4.2 Check Mode (CI & Pre-Commit)
Verifies that generated files are 100% up-to-date, untampered, and pure:
```bash
# From api directory:
cd api
npm run sync:shared:check

# Or from repository root:
npm run sync:check
```
*If any difference is found (e.g. someone edited a file directly in `web/src/shared/` or forgot to run sync after modifying a contract file), the command exits with exit code 1.*

### 4.3 Watch Mode (Active Development)
Continuously watches `api/src/contract/` for edits and syncs immediately on save:
```bash
cd api
npm run sync:shared:watch
```

## 5. Troubleshooting & FAQs

### "Error: Accidental direct modification in web/src/shared"
**Symptom**: CI fails on `npm run sync:shared:check`.
**Cause**: A developer edited a file inside `web/src/shared/` or `mobile/src/shared/` instead of `api/src/contract/`.
**Fix**:
1. Copy your edits to the matching file in `api/src/contract/`.
2. Run `npm run sync:shared` inside `api/`.
3. Stage and commit both `api/src/contract/` and the regenerated files.

### "Error: Contract file imports banned dependency 'crypto'"
**Symptom**: `sync:shared` fails with a purity error.
**Cause**: A contract file imported a Node-specific module like `node:crypto`.
**Fix**:
Use standard Web Crypto APIs (`globalThis.crypto`) or isomorphic pure JS algorithms that run identically in V8, browsers, and React Native Hermes.

### "How do import aliases work across the three folders?"
All three folders use the same `@ap/*` import specifiers:
- `@ap/shared-types`
- `@ap/shared-constants`
- `@ap/shared-validation`
- `@ap/api-client`
- `@ap/design-tokens`
- `@ap/shared-i18n`

Path mappings:
- In `api`: mapped to `./src/contract/*` via `api/tsconfig.json` and inlined by `tsup`.
- In `web`: mapped to `./src/shared/*` via `web/tsconfig.json` and resolved by Vite.
- In `mobile`: mapped to `./src/shared/*` via `mobile/tsconfig.json` and resolved by Metro.
